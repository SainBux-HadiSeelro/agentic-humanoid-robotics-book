# Data Model: Vision-Language-Action (VLA) Module

## Overview
This document defines the key data structures for the VLA educational module, derived from the feature specification and research findings.

## Core Entities

### VoiceCommand
- **Description**: Natural language instruction provided by the user that needs to be processed and translated into robot actions
- **Fields**:
  - id: string (unique identifier)
  - text: string (transcribed speech content)
  - audioData: optional binary (raw audio input)
  - timestamp: datetime (when command was received)
  - confidence: number (0-1, speech recognition confidence)
  - status: enum (pending, processed, failed, executed)
  - metadata: object (additional information about the command)

### CognitivePlan
- **Description**: Sequence of actions generated by the LLM that represents the robot's strategy for completing a task
- **Fields**:
  - id: string (unique identifier)
  - commands: array of objects (sequence of actions to execute)
  - reasoning: string (explanation of how the plan was derived)
  - timestamp: datetime (when plan was generated)
  - status: enum (pending, executing, completed, failed)
  - sourceCommandId: string (reference to originating VoiceCommand)
  - confidence: number (0-1, plan confidence score)

### ROS2ActionSequence
- **Description**: Specific commands in ROS 2 format that control the simulated robot's behavior
- **Fields**:
  - id: string (unique identifier)
  - actions: array of objects (individual ROS 2 actions)
  - actionType: string (type of action: movement, manipulation, sensing, etc.)
  - parameters: object (specific parameters for each action)
  - timestamp: datetime (when sequence was created)
  - sourcePlanId: string (reference to originating CognitivePlan)
  - status: enum (pending, executing, completed, failed)

### VisionInput
- **Description**: Image or visual data that the system processes to understand the environment for vision-language-action tasks
- **Fields**:
  - id: string (unique identifier)
  - imageData: binary (image data)
  - description: string (textual description of the image)
  - objects: array of objects (detected objects in the image)
  - timestamp: datetime (when image was processed)
  - metadata: object (additional image information)

### SimulatedRobot
- **Description**: Virtual representation of a humanoid robot that executes the planned actions in a safe educational environment
- **Fields**:
  - id: string (unique identifier)
  - name: string (robot name)
  - position: object (x, y, z coordinates)
  - orientation: object (rotation angles)
  - status: enum (idle, moving, executing, paused)
  - capabilities: array of strings (what the robot can do)
  - environment: string (current simulation environment)

### StudentInteraction
- **Description**: Record of student interactions with the VLA system for educational tracking
- **Fields**:
  - id: string (unique identifier)
  - studentId: string (identifier for the student)
  - commandId: string (reference to VoiceCommand)
  - planId: string (reference to CognitivePlan)
  - sequenceId: string (reference to ROS2ActionSequence)
  - timestamp: datetime (when interaction occurred)
  - outcome: string (result of the interaction)
  - feedback: string (student feedback or assessment)

## Relationships
- VoiceCommand → CognitivePlan (one-to-many)
- CognitivePlan → ROS2ActionSequence (one-to-one)
- VisionInput → CognitivePlan (many-to-many, through vision-enhanced planning)
- SimulatedRobot → ROS2ActionSequence (one-to-many, executes sequences)
- StudentInteraction → VoiceCommand, CognitivePlan, ROS2ActionSequence (many-to-one each)

## Validation Rules
- VoiceCommand.text must not be empty
- CognitivePlan.commands must contain at least one action
- ROS2ActionSequence.actionType must be one of the defined action types
- VisionInput.imageData must be a valid image format
- Confidence values must be between 0 and 1

## State Transitions

### VoiceCommand States
- pending → processed (when speech recognition completes)
- pending → failed (when speech recognition fails)
- processed → executed (when action sequence completes)
- processed → failed (when action sequence fails)

### CognitivePlan States
- pending → executing (when action sequence starts)
- executing → completed (when all actions complete successfully)
- executing → failed (when any action fails)

### ROS2ActionSequence States
- pending → executing (when simulation starts)
- executing → completed (when simulation ends successfully)
- executing → failed (when simulation encounters error)
